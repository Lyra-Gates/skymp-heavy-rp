# SkyMP Heavy RP — ролевой сервер для Skyrim в мультиплеере

*[Português](README.md) · [English](README.en.md) · **Русский** · [Español](README.es.md)*

Открытая и актуальная **база RP-сервера для Skyrim Special Edition в мультиплеере**, построенная поверх [SkyMP](https://github.com/skyrim-multiplayer/skymp). Игровой режим на Node.js, панель вайтлиста, лаунчер на Electron и проверка соответствия модпака.

Сделано под *строгий ролевой отыгрыш*: сервер решает всё, что касается экономики, личности персонажа и последствий, — не ломая при этом сетевую синхронизацию.

> **Зачем это нужно:** на август 2026 года у сообщества SkyMP нет ни одной открытой и поддерживаемой базы RP-сервера. Единственная публичная — [Red House](https://github.com/alekcey0211/red-house-public) — заброшена с 2021 года. Этот проект пытается закрыть эту дыру.

> ⚠️ **К продакшену пока не готово.** Игровой режим проверен только автотестами против замоканного `mp` — **ничего не проверялось в реальной игровой сессии**. Честное состояние каждого компонента — в [отчёте QA](docs/technical/QA_REPORT_2026-08.md).

## Что внутри

| Компонент | Что делает |
|---|---|
| `skymp/gamemode` | Игровой режим на Node.js: RP-чат, управление (аресты, штрафы, налоги), торговые лавки игроков, смерть с последствиями, внутриигровая панель, голос по расстоянию |
| `skymp/ui` | Внутриигровой интерфейс на CEF |
| `apps/web` | Панель администрации, вайтлист, Discord OAuth и **мастер-API SkyMP**, благодаря которому личность игрока определяет сервер, а не клиент |
| `apps/game-api` | Порт 7758: соответствие модпака (`/mods.json`) и очередь на вход |
| `apps/bot-discord` | Синхронизация ролей и временные голосовые каналы |
| `apps/launcher` | Лаунчер на Electron + React: обновление клиента и модпака, проверка целостности, очередь |
| `skymp/packages/database` | Схема MariaDB и миграции |

### Чего нет больше нигде

- **Типизация API `mp`** ([`types/mp.d.ts`](skymp/gamemode/types/mp.d.ts)) — SkyMP не публикует типов.
- **Карта настоящего API SkyMP** ([`SKYMP_UPSTREAM_REFERENCE.md`](docs/technical/SKYMP_UPSTREAM_REFERENCE.md), на португальском), включая хуки, которых нет в официальной документации, — вытащены из интеграционных тестов самого SkyMP.
- **Рабочее мастер-API сессий** — большинство тестовых серверов работает в `offlineMode`, где клиент сам объявляет, кто он, а сервер ему верит.
- **Атомарная экономика** с журналом операций ([`core/transaction-service.js`](skymp/gamemode/core/transaction-service.js)).
- **Проверка соответствия модпака** с генератором манифеста.

## Запуск

Нужны **Node.js 20+**, **MariaDB/MySQL** и **Skyrim SE/AE** для проверки в игре.

```bash
git clone https://github.com/vinicius3232/skymp-heavy-rp.git
cd skymp-heavy-rp

# У каждого сервиса свои зависимости
cd skymp/gamemode   && npm ci && cd ../..
cd apps/web         && npm ci && cd ../..
cd apps/game-api    && npm ci && cd ../..
cd apps/bot-discord && npm ci && cd ../..
```

Скопируйте каждый `.env.example` в `.env` и заполните — комментарии внутри объясняют, откуда берётся каждое значение. Примените `schema.sql`, затем миграции с `v2` по `v8`, **по порядку**.

```powershell
.\scripts\phase0\Start-AllServices.ps1
```

Скрипт сначала проверяет `.env` и `node_modules` у каждого сервиса и говорит, что не поднимется, вместо того чтобы отрапортовать об успехе с мёртвым сервисом.

### Инструменты отладки, о которых обычно не знают

- **`localhost:9000`** в обычном браузере открывает **DevTools встроенного браузера игры** — консоль, инспектор и точки останова для внутриигрового интерфейса. Без этого интерфейс отлаживается вслепую.
- Сервер **проксирует запросы интерфейса на dev-сервер на порту 1234**, так что CSS/JS можно править без перезапуска.

## Язык документации

Входные документы переведены. **Глубокая техническая документация остаётся на португальском** — намеренно.

Это решение по сопровождению, а не недосмотр. Около 26 технических документов меняются часто, а устаревший перевод хуже отсутствующего: это документ, которому доверяют, а он тихо врёт. Одна авторитетная версия хотя бы остаётся верной.

Если конкретный документ вас блокирует — [спросите в Discussions](https://github.com/vinicius3232/skymp-heavy-rp/discussions/categories/q-a), переведём именно его. Машинный перевод справляется с этими файлами неплохо: это обычный Markdown.

## Смежные проекты

Тот, кто ищет ролевой сервер для Skyrim в мультиплеере, обычно натыкается на эти. Карта помогает понять, кто где:

| Проект | Что это | Состояние |
|---|---|---|
| [skyrim-multiplayer/skymp](https://github.com/skyrim-multiplayer/skymp) | Платформа. Сервер на C++, Skyrim Platform и SDK на TypeScript. **Этот проект работает поверх неё.** | Активен |
| [alekcey0211/red-house-public](https://github.com/alekcey0211/red-house-public) | Публичная сборка RP-сервера, GPL-3.0. Единственная, что существовала. Подробный разбор — [здесь](docs/technical/REFERENCE_STUDY_SKYMP_RED_HOUSE.md). | Заброшен с 2021 |
| [alekcey0211/skymp5-scripts](https://github.com/alekcey0211/skymp5-scripts) | Papyrus-скрипты для RP, тот же автор, что и у Red House. | Заброшен с 2021 |
| [skyrim-roleplay](https://github.com/skyrim-roleplay) (Keizaal Online) | Организация RP-сервера. Форк SkyMP открыт, игровой режим — нет. | Активен, RP-код закрыт |
| [Silveira-Software/SKYRIMRP-BR](https://github.com/Silveira-Software/SKYRIMRP-BR) | Бразильский RP-сервер. Репозиторий только для анонсов — код закрыт. | Активен, код закрыт |

**Дыра, которую пытается закрыть этот проект:** у активных серверов игровой режим закрыт, а единственный открытый стоит без движения уже несколько лет. Тому, кто хочет поднять RP-сервер сегодня, попросту не от чего оттолкнуться.
