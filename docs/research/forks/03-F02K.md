# 03 — F02K/skymp

## Resumo e diferença do upstream

Snapshot `52c3478` (2026-07-25): 13 commits à frente, 1 atrás, 130 arquivos divergentes. É o fork mais valioso para infraestrutura e distribuição.

## Sistemas e fluxo

```text
buildtool/doctor -> deterministic client pack -> canonical manifest + SHA-256
  -> managed backend/supervisor -> directory registration (timestamp+nonce+Ed25519)
  -> launcher session handoff -> SkyMP auth -> reconnect/session storage
```

- `skymp-backend`: config schema, module loader/router, supervisor, storage, setup CLI, directory connector.
- `skymp-buildtool`: profiles, doctor, CMake/build actions, client pack/mod collection e TUI, com testes.
- `skymp5-gamemode-compiler`: config schema, builder/checker/types e testes.
- Segurança concreta: canonical JSON, SHA-256, Ed25519, nonce/timestamp, public-key pinning, token hashing e redaction de chaves sensíveis no logger.

## Maturidade

Client pack/buildtool é `PRODUCTION_READY candidate`, não validado no ambiente Heavy RP. Backend/supervisor/auth e compiler são `FUNCTIONAL_PROTOTYPE` com boa cobertura relativa. O storage contém alternativas SQLite/PostgreSQL; nenhuma deve ser transplantada — o Heavy RP implementará o padrão com `mysql2/promise` e MariaDB.

## Segurança e performance

Risco residual `MEDIUM`: pinning/rotação de chave, proteção da signing key, replay window, revogação, path traversal no pack, zip bomb, rollback e indisponibilidade do directory precisam de threat model. Supervisor deve ter backoff/jitter e limite de restart. Hashing de pack é operação de build/startup, nunca por tick.

## Recomendação

`ADAPT / USE_NOW`: manifesto canônico assinado, verificação de load order, sessões opacas, redaction, doctor, supervisor e packaging reproducível. Não copiar o banco, o directory service nem substituir o launcher inteiro. Licença detectada como `NOASSERTION`/`TERMS.md`: padrões podem inspirar; código literal requer revisão e notices.
