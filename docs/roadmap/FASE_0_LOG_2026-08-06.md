## Consultas do teste

Deixadas aqui para não precisar voltar ao roteiro no meio da sessão.

**1.6 — a identidade veio do servidor, não do cliente** *(o teste mais importante)*
```sql
SELECT id, account_id, discord_id, resolve_count, last_resolved_at, expires_at, revoked_at
FROM game_sessions ORDER BY id DESC LIMIT 1;
```
`resolve_count = 0` significa que o master API **não** foi chamado — o servidor está em `offlineMode` ou o `master` não aponta para o painel. Se isso falhar, todo o resto roda sobre identidade forjável.

**5.2 — `mp.onDeath` disparou (autoria da morte)**
```sql
SELECT * FROM audit_logs WHERE action = 'death:killer' ORDER BY id DESC LIMIT 1;
```
Vazio = o hook não disparou e quem pegou a morte foi o polling. Nesse caso o QA 1.8 continua bloqueado.
