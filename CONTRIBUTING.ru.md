# Как участвовать

*[Português](CONTRIBUTING.md) · [English](CONTRIBUTING.en.md) · **Русский** · [Español](CONTRIBUTING.es.md)*

Спасибо за интерес. Это публичная база RP-сервера для SkyMP под AGPL-3.0 — всё, что вы сюда добавите, останется доступным всему сообществу.

Документ состоит из двух частей: как запустить и как прислать изменения, и **правила, которые не видны при чтении кода**. Вторая часть важнее — почти каждый её пункт существует потому, что кто-то уже на этом обжёгся.

---

## 1. Поднимаем окружение

Нужны **Node.js 20+**, **MariaDB/MySQL** и **Skyrim SE/AE**, если собираетесь проверять в игре.

```bash
git clone https://github.com/vinicius3232/skymp-heavy-rp.git
cd skymp-heavy-rp

cd skymp/gamemode   && npm ci && cd ../..
cd apps/web         && npm ci && cd ../..
cd apps/game-api    && npm ci && cd ../..
cd apps/bot-discord && npm ci && cd ../..
cd apps/launcher    && npm ci && cd ../..
```

Скопируйте каждый `.env.example` в `.env` и заполните — комментарии внутри объясняют, откуда берётся каждое значение.

База: примените `skymp/packages/database/schema.sql`, затем все доступные миграции (сейчас с `v2` по `v26`), **по номеру версии**.

```powershell
.\scripts\phase0\Start-AllServices.ps1
```

Скрипт проверяет `.env` и `node_modules` у каждого сервиса и говорит, что не поднимется. Если он ругается — чините то, на что он показывает: он не врёт из оптимизма.

### Отладка

Две вещи, которые есть и которыми почти никто не пользуется:

- **`localhost:9000`** в браузере открывает **DevTools встроенного браузера игры**. Именно так отлаживается интерфейс из `skymp/ui/`. Без этого вы работаете вслепую.
- Сервер **проксирует запросы интерфейса на dev-сервер на порту 1234**, так что CSS/JS интерфейса можно править без перезапуска.

## 2. Запуск тестов

```bash
cd skymp/gamemode   && npm test && npm run test:systems && npm run typecheck
cd apps/web         && npm test
cd apps/game-api    && npm test
cd apps/bot-discord && npm test
cd apps/launcher    && npm run typecheck

# Нужна база: проверяет, что она соответствует версионированным миграциям
cd skymp/gamemode   && npm run check:schema
```

Используется встроенный тест-раннер Node (`node --test`) — без Jest, без Vitest, без конфигурации.

**Новый тест нужно вписать в скрипт `test` в `package.json`.** Автопоиска файлов нет: тест, которого нет в списке, просто не запускается, и никто этого не замечает.

## 3. Правила, которые не очевидны

Это сердце документа. Каждый пункт здесь — из-за реальной поломки.

### 3.1 Деньги: только через `core/economy-service.js`

**Никогда** не пишите `UPDATE characters SET gold = ...`, `UPDATE cities SET treasury = ...` и подобное. И с 13.08.2026 не вызывайте примитивы `tx.*` из `transaction-service` в модуле предметной области.

Дверь — [`core/economy-service.js`](skymp/gamemode/core/economy-service.js) ([фреймворк](docs/framework/ECONOMY_FRAMEWORK.md), [ADR 004](docs/technical/ADR_004_ECONOMY_ACCOUNTS_AND_LEDGER.md)). Он проверяет сумму, блокирует оба счёта в каноническом порядке, проверяет идемпотентность **внутри** транзакции и пишет **обе стороны** в журнал с общим `transfer_id`.

`core/transaction-service.js` никуда не делся и остаётся единственным файлом, который пишет `characters.gold` — это движок, а не API. Прежний `economy-service.js`, удалённый 06.08.2026, делал голые `UPDATE` и `removeGold` с последующим `addGold` без транзакции; сегодняшний — его противоположность, и имя вернулось потому, что вернулась роль.

```js
// правильно
await economy.transfer({
  from: { type: 'character', ref: payerId },
  to:   { type: 'city', ref: 'whiterun' },
  amount, reason: 'guard_fine', module: 'governance',
  actorCharacterId: guardId, idempotencyKey: requestId
});

// неправильно — нет второй стороны в журнале, у казны нет истории
await conn.query('UPDATE cities SET treasury = treasury + ? WHERE id = ?', [amount, cityId]);
```

**Отказ — это не сбой.** `{ok:false, code}` — это решение по правилу; сбой инфраструктуры **бросает исключение**. Никогда не путайте одно с другим — именно из-за этого таймаут базы превращался в ордер на арест при штрафе стражи ([аудит, находка 7](docs/research/ECONOMY_FRAMEWORK_AUDIT.md)).

Для **предметов** дверь — [`core/inventory.js`](skymp/gamemode/core/inventory.js) ([фреймворк](docs/framework/INVENTORY_FRAMEWORK.md)). Никогда не трогайте `character_inventory` напрямую.

### 3.2 Papyrus: `self` — это объект, а не FormID

Используйте хелперы из `core/papyrus.js`:

```js
const { actorRef, baseRef } = require('./core/papyrus');
mp.callPapyrusFunction('method', 'Actor', 'Resurrect', actorRef(actorId), []);
```

В игровом режиме обе формы уже были перемешаны в 22 местах. Девять собственных интеграционных тестов SkyMP (`misc/tests/` в upstream) используют **исключительно** объектную форму, в том числе для аргументов-ссылок. `type: 'form'` — для того, что существует в мире, `type: 'espm'` — для базовых записей плагина.

### 3.3 Модули: только через `core/module-registry.js`

Новый сервис регистрируется в `phase0-basic.js` с `id`, `enabledBy` (флаг `ENABLE_*`), `dependencies`, `commands` и `initialize()`. Реестр сам разрешает зависимости и регистрирует/снимает команды.

**Никогда не импортируйте PARKED-модуль напрямую.** Семь сервисов лежат на диске и не работают (`economy-regional`, `crafting`, `jobs`, `housing`, `horse`, `trade`, `disguise`). Импорт при старте заставит их работать в обход флагов — ровно то, ради предотвращения чего реестр и существует.

### 3.4 `server-options.json`: только то, что реально подключено

В `core/server-options.js` два списка: `SPEC` (опции, которые действительно меняют поведение) и `DECLARED_BUT_UNWIRED` (те, что пока ничего не делают).

Реализовали опцию — **перенесите её из одного списка в другой**. Есть тест, который не даёт файлу-примеру обзавестись новым ключом без классификации.

Так вышло потому, что в схеме было 24 задокументированные опции и **ни одна не читалась**: человек ставил `permadeathEnabled`, ничего не происходило, и он делал вывод, что сервер сломан. Конфиг, который выглядит настоящим и ничего не делает, хуже, чем отсутствие конфига.

### 3.5 Права: по имени, никогда по номеру

`admin-service.hasPermission(actorId, 'retire_character')`. Функция отвергает числа и неизвестные имена, записывая ошибку в лог, — но не полагайтесь на это, пишите правильно сразу.

Было двенадцать вызовов с числовым уровнем (`hasPermission(id, 20)`) против `Set` строк. `Set.has(20)` всегда `false`, так что они молча запрещали всё.

### 3.6 Клиенту нельзя доверять

Золотое правило проекта: **сервер решает, клиент показывает.**

События из `mp.makeEventSource` выполняются на клиенте. Это **подсказка**, а не доказательство. Годится, чтобы заметить смерть; не годится, чтобы выдать предмет или золото.

Та же логика в `apps/web`: `discordId` публичен и ничего не доказывает. Аутентификация — по тикету, выданному тем, у кого есть секрет.

### 3.7 Никогда не делайте `DELETE` персонажу

Персонаж уходит из игры через `status = 'retired'`. История — журналы аудита, транзакции, судимости — должна пережить это. `whitelist.js` пускает в спавн только со `status = 'approved'`, так что `retired` уже достаточно.

Осторожнее с `UPDATE ... JOIN` по аккаунту: однажды одобрение вайтлиста воскресило персонажа, которому сделали `/permakill`. Фильтруйте по статусу.

### 3.8 Вызов Papyrus стоит дорого

Каждый round-trip в Papyrus стоит **десятки миллисекунд** — RP-сервер Red House намерил 13–35 мс на вызов. Это не микросекунды.

Из-за этого поллинг быстро становится дорогим. Предпочитайте нативные хуки (`mp.onDeath`, `mp.onActivate`) и `mp.makeEventSource` циклам `setInterval` с `getActorValue`. Там, где поллинг ещё остался, он помечен как долг.

### 3.9 Секрет никогда не идёт в переменную `VITE_`

Всё, что `VITE_*` в лаунчере, **вшивается в инсталлятор на этапе сборки** и уезжает к игрокам. Client secret Discord когда-то жил там — сейчас он только в `apps/web`, который и обменивает токен.

### 3.10 Секрет души не покидает сервер — и домен не читает окружение

`core/soul.js` выводит душу персонажа из **его одобренной заявки**, подписанной серверным секретом. Отсюда два правила, и оба легко нарушить незаметно.

**Секрет передаётся аргументом, а не читается из `process.env` внутри модуля.** Домен не знает об инфраструктуре — именно это позволяет тестировать файл без сервера, без базы и без `mp`. Один `require('dotenv')` внутри разрушает всё свойство.

**Секрет не должен утечь никуда**: ни в лог, ни в payload, ни в ответ API. Заявка персонажа публична. С секретом любой вычислит чужую душу из того, что написано в панели, — и вся система разом перестаёт быть скрытой, без единой ошибки в логе.

По той же причине: **ни одно число родства не должно дойти до клиента.** Игрок получает знаки и последствия, но не значения. См. [`docs/design/SOUL_AFFINITY.md`](docs/design/SOUL_AFFINITY.md) §III.12.7 (на португальском) — это тест, который защищает систему целиком.

### 3.11 Невидимый символ в исходнике — всегда escape, никогда сырой байт

Пишите `'\u0000'`, `[\u0300-\u036f]`, `'\t'`. Никогда не вставляйте сам символ.

В `core/soul.js` их было два: класс комбинирующих знаков в `normalize()` и — что хуже — NUL как разделитель полей, которые идут в HMAC души. NUL там выбран правильно: он не переживает `normalize()`, поэтому ни один игрок не сможет вписать его в заявку. Без разделителя, который невозможно набрать, `'ab'+'c'` и `'a'+'bc'` подписали бы один и тот же материал — и две разные заявки родились бы с одной душой.

Проблема была не в выборе, а в том, что он был невидим. Три последствия, все молчаливые:

- **Строка врёт читателю.** `].join('<NUL>')` выглядит на экране как `].join('')` — ревьюер понимает «склеить без разделителя», то есть ровно наоборот.
- **Файл становится бинарным.** `grep` отвечает `Binary file matches` вместо фрагмента, а `file` говорит `data`. Инструмент, которым все ищут код, перестаёт работать с этим файлом.
- **Редактор может удалить символ при сохранении.** Многие вычищают управляющие символы. В этом файле такое переписало бы семя **всех уже выведенных душ**, и ни одной ошибки бы не появилось.

Если невидимое значение несёт смысл, оно заслуживает именованной константы и комментария о том, почему значение именно такое. В `core/soul.test.js` есть статическая проверка на оба случая.

## 4. Стиль кода

- **Португальский** в комментариях, документации и сообщениях игроку. Идентификаторы — на английском, как в файле, который вы правите.
- **Комментарий объясняет «почему», а не «что».** `// увеличиваем i` не помогает никому; `// FOR UPDATE здесь, потому что две одновременные покупки дублировали предмет` помогает очень.
- **В игровом режиме нет шага сборки.** Это чистый JS, который SkyMP грузит напрямую. `npm run typecheck` использует `types/mp.d.ts` и носит справочный характер — не вводите компиляцию, это добавит шаг в самый медленный цикл проекта (правка → проверка в игре).
- Следуйте стилю файла, который правите, даже если сами написали бы иначе.

### Типизация API `mp`

`skymp/gamemode/types/mp.d.ts` помечает происхождение каждой сигнатуры: `[DOC]` — то, что есть в официальной документации SkyMP, `[USO]` — то, что выведено из нашего использования.

Открыли что-то новое в реальном тесте — добавьте с пометкой `[USO]` и укажите, где это наблюдалось. Различие важно: `[USO]` может измениться без предупреждения в обновлении SkyMP.

## 5. Коммиты и Pull Request'ы

Используем [Conventional Commits](https://www.conventionalcommits.org/):

```
feat(gamemode): adiciona zona segura por celula
fix(web): valida redirect_uri antes de trocar o code
docs: documenta o contrato de FormID
```

Используемые скоупы: `gamemode`, `web`, `game-api`, `bot-discord`, `launcher`, `schema`.

Сообщения коммитов пишутся на португальском, в тон кодовой базе, но **английский вполне подойдёт**, если так вам привычнее — понятное сообщение по-английски лучше непонятного по-португальски.

**Объясняйте «почему» в теле коммита.** История этого проекта — настоящий источник контекста; несколько коммитов объясняют решения, которые не помещаются в код.

### Перед открытием PR

- [ ] Тесты проходят в сервисах, которые вы затронули
- [ ] `npm run typecheck` чистый, если трогали игровой режим или лаунчер
- [ ] Новый тест на новое поведение — проверяющий **аргумент**, а не только результат (см. §6)
- [ ] Документация обновлена, если изменилось поведение или архитектура
- [ ] В диффе нет секретов, настоящего `.env` и ассетов Bethesda

## 6. О тестах, которые дают ложную уверенность

Заслуживает отдельного предупреждения, потому что нам это дорого обошлось.

Глобальный `mp` в тестах замокан. **Мок принимает что угодно** — так 22 вызова Papyrus с неправильной формой аргумента месяцами держали сюиту зелёной. Хуже того: из-за guard'ов `if (typeof mp === 'undefined') return;` тесты до этого кода даже не доходили.

Когда тестируете что-то, что говорит со SkyMP или с базой, **проверяйте переданный аргумент**, а не только возвращаемое значение:

```js
// слабо: пройдёт даже при неправильном формате
assert.equal(await service.giveItem(...), true);

// сильно: ловит нарушение контракта
assert.equal(typeof call.self, 'object', 'self должен быть объектом, а не FormID');
assert.match(query.sql, /FOR UPDATE/, 'без блокировки две покупки дублируют предмет');
```

Примеры — в `core/papyrus.test.js` и `apps/web/server.test.js`.

## 7. Как сообщать о проблемах

- **Вопрос, сырая идея или просьба о помощи**: [Discussions](https://github.com/vinicius3232/skymp-heavy-rp/discussions). Там ответ останется видимым для следующего.
- **Баг или конкретное предложение**: откройте issue. Укажите сервис, что ожидали и что произошло.
- **Уязвимость**: **не открывайте публичный issue** — см. [SECURITY.ru.md](SECURITY.ru.md).
- **Вопрос про мод**: [контракт «моды × игровой режим»](docs/technical/MODS_AND_GAMEMODE_CONTRACT.md) §4 — тест из четырёх вопросов, который закрывает большинство случаев.
